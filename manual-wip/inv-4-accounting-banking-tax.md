# Panalo Accounts: Accounting, Banking, Tax (reference for the manual writer)

Source: accounts/app.js, accounts/views/*.js, supabase/functions/finance-api/{ledger,banking,tax,assets}.ts, supabase/migrations/{20261008000000_ledger_core,20261009000000_sales_purchasing,20261012000000_banking,20261013000000_bas,20261015000000_assets}.sql, docs/*.md. Date of research: 2026-10-08. Nothing in the repo was modified.

## 0. Headline answers

- Journal approval threshold: NONE. Workflow is save draft (needs "Create journals" ledger.journal) then post (needs "Approve and post journals" ledger.post). Segregation is by role only. Anyone holding ledger.post can "Save and post" their own journal. The accountant role has journal but not post, so its drafts always need a second person.
- Reconciliation concludes with an explicit step: the "Complete reconciliation" button on the Reconcile tab. There is no per-line tick-off. Completing sets reconciliation_id on every non-new statement line dated on or before the statement date; those lines show a "Reconciled" chip and are locked. Only the LATEST reconciliation can be undone (with a reason).
- No live bank feed. Statements come from file import (CSV, OFX/QFX, QIF) parsed in the browser.
- No dedicated Transfer feature and no "split one statement line across several statement lines". Transfer = "Spend money" coded to another bank account. "Split" = "Split into another line" in Spend/Receive money (UI max 5 account lines; API slices to 20). One statement line may match several existing ledger lines.
- BAS and TPAR are marking only. UI text: "Nothing is sent to the ATO from this system." No electronic lodgement file (TPAR gives a CSV).
- Reversal limits: only source 'manual' journals can be reversed (others: "This journal was posted by a <source>. Void the <source> itself instead, so the two stay in step."), though the UI still shows Reverse. BAS journals, asset disposal/depreciation journals and bank-matched journals cannot be reversed.
